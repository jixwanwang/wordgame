# Client Analytics

Frontend usage analytics are sent to PostHog (US region). The integration lives in `client/src/lib/analytics.ts`.

## Setup

Configured via the `VITE_POSTHOG_API_KEY` environment variable (read by Vite at build time, embedded in the client bundle — PostHog project keys are public ingestion keys, safe to expose).

If the key is missing or empty, the analytics module is a silent no-op. This is the expected dev behavior when no `.env` is present.

Initialization happens once in `client/src/main.tsx` via `initAnalytics()` before the React tree mounts.

## PostHog Configuration

| Option | Value | Why |
|---|---|---|
| `api_host` | `https://us.i.posthog.com` | US region |
| `autocapture` | `false` | Events are explicit; we don't want every click captured |
| `capture_pageview` | `true` | Free unique-visitor tracking on `/` and `/hard` |
| `disable_session_recording` | `true` | Privacy + bundle weight |
| `disable_surveys` | `true` | Not used |

## Events

All custom events live in `client/src/lib/analytics.ts` and are dispatched from `client/src/store/thunks/gameThunks.ts`.

### `puzzle_viewed`

Fired in `fetchPuzzleThunk` after the puzzle loads. Captures every puzzle load — including reloads, resumes, and past-puzzle visits.

| Property | Type | Source |
|---|---|---|
| `difficulty` | `"normal" \| "hard"` | thunk parameter |
| `puzzle_date` | `MM-DD-YYYY` | loaded puzzle |
| `is_past_puzzle` | `boolean` | `puzzle.date !== getTodayInPacificTime()` |
| `is_authenticated` | `boolean` | `Auth.isAuthenticated()` |
| `hints_shown` | `boolean` | `localStorage.getItem(STORAGE_KEY) === null && puzzle.date === today` |

`hints_shown` mirrors the new-user condition in `client/src/hooks/use-hint-text.ts:20`. It is `true` only for someone with no local history playing today's puzzle — the same audience that sees the in-game hint overlay.

### `puzzle_started`

Fired in `makeGuessThunk` when the user submits their first guess (`gameState.guesses.length === 0` before the guess is appended). Distinguishes engaged players from bouncers.

Same properties as `puzzle_viewed` minus `hints_shown`.

### `puzzle_guess`

Fired in `makeGuessThunk` for every guess that consumes a turn. Skipped duplicate-letter guesses (which don't consume a turn) are not tracked.

| Property | Type | Notes |
|---|---|---|
| `guess_type` | `"letter" \| "word"` | |
| `guess_value` | `string` | uppercased |
| `guess_number` | `number` | 1-indexed (1 to 15) |
| `is_correct` | `boolean` | letter: appears in any puzzle word; word: is one of the puzzle's words |

Plus all base properties (`difficulty`, `puzzle_date`, `is_past_puzzle`, `is_authenticated`).

### `puzzle_completed`

Fired in `makeGuessThunk` when the game transitions to `won` or `lost`.

Adds:
| Property | Type |
|---|---|
| `won` | `boolean` |
| `guesses_used` | `number` (length of guesses array at completion) |
| `letters_revealed` | `number` (0–20) |

## Funnel

The custom events plus auto pageview yield the typical funnel:

```
$pageview  →  puzzle_viewed  →  puzzle_started  →  puzzle_guess (×N)  →  puzzle_completed
                                                                              ↳ won=true
                                                                              ↳ won=false
```

`$pageview` count > `puzzle_viewed` count is normal — pageview also fires on routes like `/hard` before the puzzle resolves.

## Identity

PostHog automatically attaches two identity properties to every event:

- **`distinct_id`** — anonymous, persistent per-browser ID generated by PostHog and stored in its own localStorage entry. Survives across sessions on the same browser/device.
- **`$session_id`** — auto-rotates after 30 minutes of inactivity (or 24 hours).

When a user logs in or registers, `Auth.setUsername()` calls `identifyUser(username)` (in `client/src/lib/analytics.ts`), which invokes `posthog.identify(username)`. From that point on, events are attributed to the username, and PostHog automatically merges prior anonymous events from the same browser into the identified person.

On logout, `Auth.logout()` calls `resetAnalyticsUser()` which invokes `posthog.reset()` — a fresh anonymous `distinct_id` is generated so subsequent activity isn't attributed to the prior user.

On app boot (`client/src/main.tsx`), if the username cookie is present (returning logged-in user), `identifyUser()` is called immediately after `initAnalytics()` so events from that session are attributed correctly from the first event.

### Summary
| User state | distinct_id |
|---|---|
| Anonymous (never logged in) | persistent random ID per browser |
| Authenticated | username |
| After logout | fresh random ID per browser |
